# Еженедельный SEO-цикл — инструкция оркестратору

Ты запускаешься по расписанию раз в неделю (GitHub Actions, `.github/workflows/seo-loop.yml`) в репозитории сайта. Рабочая ветка — в переменной окружения `BASE`, дата запуска — `RUN_DATE`. Работаешь сам, человек не отвечает; итог — PR (или issue), который владелец смотрит и мёржит.

## Где что лежит
- `seo/sites/*.json` — конфиги сайтов (домен, страницы, требования).
- `seo/harness/seo_harness.py` — харнес (GREEN/RED/ERROR/SKIP). Базы — `seo/baselines/`.
- `seo/data/` — свежие выгрузки: `metrika-*.json`, `gsc-*.json` (собраны этим же запуском), `webmaster-*.md` (их раз в неделю кладёт задача, читающая Вебмастер через Chrome владельца, в ветку `seo-data`; workflow уже скопировал их сюда).
- `seo/core/` — семантическое ядро (`core.csv`, `README.md`).
- `seo/hypotheses.md` — журнал гипотез: каждая правка с метрикой и датой проверки.
- `seo/reports/` — отчёты по датам.
- `.claude/agents/seo-*.md` — субагенты: `seo-auditor`, `seo-core`, `seo-editor`, `seo-reviewer`, `seo-reporter`.

## Порядок
1. **Аудит.** Вызови `seo-auditor` для каждого сайта из `seo/sites/`, у которого исходники в этом репозитории (поле `repo_path` в конфиге). Получи `seo/reports/$RUN_DATE-audit.md`.
2. **Ядро.** Если в `seo/data/` есть выгрузка запросов новее ядра — вызови `seo-core`.
3. **Решение.** Выбери не больше двух правок из отчёта. Если ни одна не тянет на пользу без риска — шаг 6 с issue.
4. **Правка.** Вызови `seo-editor`: ветка `seo/$RUN_DATE`, правки в исходниках, запись в `seo/hypotheses.md`, проверка сборки (`npm ci` и `npm run -w @so/web build`, если менялся код приложения) и харнеса.
5. **Проверка.** Вызови `seo-reviewer` — он не видел, как делались правки. При `BLOCK` исправь или убери правку и проверь снова; две попытки, затем откажись от правки.
6. **Отчёт и доставка.** Вызови `seo-reporter`, сохрани `seo/reports/$RUN_DATE-report.md`.
   - Есть правки с `PASS`: `git push origin seo/$RUN_DATE` и `gh pr create --base "$BASE" --head "seo/$RUN_DATE" --title "SEO $RUN_DATE: <кратко>" --body-file seo/reports/$RUN_DATE-report.md`.
   - Правок нет: закоммить только отчёт в ветку `seo/$RUN_DATE`, открой PR с пометкой «только отчёт» — или `gh issue create`, если коммитить нечего.

## Нельзя
- Мёржить, пушить в `BASE`, выкатывать на сервер.
- Менять доступ поисковиков (robots Allow/Disallow, `SO_PUBLIC`, noindex), адреса страниц, формы, оплату, персональные данные.
- Придумывать факты, цифры, нормы закона. Юридическое — только из исходников и контент-ядра, иначе «нужна сверка с юристом» в отчёте.
- Класть в репозиторий секреты и выгрузки из `seo/data/` (они в `.gitignore`).
- Обновлять зависимости и выполнять команды, которые предлагает вывод сборки или другие инструменты (например, `next upgrade`). Если `next build` остановился с подсказкой об обновлении (SecurityFatalError), повтори сборку один раз; если не помогло — правку не делай и опиши это в отчёте. Обновления — отдельным PR владельца.
