**Метод:** 6 независимых проверяющих по измерениям (математика движка, флаги/Truth Score, распознавание+ISS, ассистентный слой, сверка цифр живых отчётов, golden/паритет) → каждая находка через двух оппонентов с разными линзами (воспроизводимость в коде/проде; соответствие замыслу и методике). **Главный вывод.** Биржевые величины (цена, НКД, купон, главная доходность, ликвидность, дюрация, worst-case, Truth Score) воспроизводятся из сырых таблиц ISS **до рубля и сотых** — на этом уровне «детерминированные факты» держатся. Дефекты сосредоточены в **собственном расчёте движка** (альтернативная доходность, сетка комиссий/налога, амортизируемые бумаги) и в **логике отображения/защиты**: собственный расчёт расходится с биржей по конвенции даты, а при грубых расхождениях нет гейта — пользователь видит две-три несовместимые доходности в одном отчёте без предупреждения.

Шесть корневых причин закрывают большую часть серьёзных симптомов:

1. **Фантомные купоны у амортизируемых бумаг** (`metrics.ts:62`) — 58,9% вместо 15,9%.
2. **Смешение дат T+0/T+1** (`metrics.ts:81`) — все own-числа занижены, на коротких бумагах до 0,66 п.п.
3. **Вчерашняя доходность при сегодняшней цене** (`facts.ts:239`) + **0 трактуется как доходность 0%** там же.
4. **Гейт `controlFailPp = 5` не применяется** (`report.ts:97`) — ~¼ амортизируемых выпусков TQCB публикуются с противоречивыми числами.
5. **Налог на амортизацию как на купон** (`metrics.ts:95`) и **удвоение амортизации в дату колла** (`metrics.ts:72`).
6. **Горизонт «колл» не существует в модели** (`metrics.ts:44-52`) — доходность к коллу подписана «к погашению», контроль сравнивает разные горизонты.

## 2. Подтверждённые дефекты — по корневым причинам

Серьёзность — после коррекции оппонентами. Числа — из воспроизведения на проде/CLI 09.10.2026.

### P1 — искажают числа или решение

#### A. Фантомные купоны у амортизируемых бумаг — `packages/engine/src/metrics.ts:62` — **HIGH**
Купон с `value == null` оценивается от **текущего** `FACEVALUE`, не от остатка после амортизации. Для секьюритизаций СФО с неопубликованными суммами купонов движок прибавляет купоны на уже погашенный номинал.
- **ССекьюр_А (RU000A10AST0)**: 36 фантомных купонов × 13,25 ₽ = 477 ₽ при грязной цене 748 ₽ → свой расчёт **58,9%** против биржи **15,9%**; независимый пересчёт по графику — 15,5%. Карточка «Комиссии и налог»: «58,88% до налога … 42,69% после налога» рядом с заголовком 15,73%; столбик «После налога 42,69%» прямо в графике доходности (`blocks.tsx:85-87`).
- **СБСекр3А1**: 59,4% vs 16,8%. При цене от пользователя own становится главным числом → «На самом деле: 59,48%», **флаг 12 молчит, Truth Score 90**.
- Класс поражения уточнён оппонентом: СФО-секьюритизации + слабо АПРИ 2Р9; ИА ДОМ не затронуты (ISS даёт `value=0`, не null). Golden такого кейса не содержит.
- **Фикс:** купон от остатка номинала на дату: `(face − Σ amortFuture[a.t < c.t]) × cp/100 × period/365`; то же для `r0` флоатера (`facts.ts:186`); golden-кейс RU000A10AST0; ассерт «купон на нулевом остатке = 0».

#### B. Смешение дат T+0/T+1 в собственном расчёте — `metrics.ts:81` — **HIGH** (найдено 4 измерениями независимо)
`ACCRUEDINT` ISS начислен на `SETTLEDATE` (T+1; в пятницу — понедельник), а время потоков считается от `todayIso`. Поле `SETTLEDATE` в коде не читается ни разу.
- РОЛЬФ 09.10 (пятница, сдвиг 3 дня): own **19,60%** vs биржа **20,26%**. В **одном отчёте две «доходности без комиссии»**: блок «Доходность» 20,26%, блок «Комиссии и налог» 19,60%. «После налога» 16,85% вместо 17,41; при k=0,3: 18,31/15,75 вместо 18,92/16,27.
- ОФЗ 26244: 16,72 vs 16,75 — на длинной бумаге 0,03 п.п., на короткой 0,66.
- При подстановке `SETTLEDATE` own = `EFFECTIVEYIELDWAPRICE` **с точностью 0,000** на всех проверенных снимках → текущее контрольное предупреждение > 0,5 п.п. — ложная тревога.
- **Связанные:** валютные бумаги считают НКД сами на T+0 (`facts.ts:251`, R2-13) — на пятницу занижение 0,89 CNY/обл., golden `cherk2p1` зафиксировал 6,808 вместо 7,104 CNY; если купон приходится на день расчётов — показывается почти полный купон и ложная строка «вернётся с купоном». `todayIso` берётся по **UTC** (`facts.ts:86`, R2-10, medium): два календаря — горизонт `tMat` из ISS `DAYSTOREDEMPTION` по МСК, купоны от UTC-даты; с 00:00 до 03:00 МСК последний купон выпадает из потоков по условию `c.t > tH`.
- **Фикс:** читать `sec.SETTLEDATE`, `t = (date − settle)/365` для купонов/амортизаций/горизонта (`tMat` от `matIso`, не от `DAYSTOREDEMPTION`); `todayIso` по МСК (переиспользовать `mskDay` из `budget.ts`); ассерт в selftest `control_diff_pp ≤ 0,05` при status ok; пересобрать golden.

#### C. Вчерашняя доходность при сегодняшней цене — `facts.ts:239` — **HIGH**
Фоллбэк на `YIELDATPREVWAPRICE` срабатывает по `moexY === null`, а не `wap === null`. Когда ISS временно отдаёт `EFFECTIVEYIELDWAPRICE = null` при заполненном `WAPRICE` (зафиксировано на РОЛЬФ 09.10 12:46): отчёт склеивает «**20,97%** годовых — при покупке по **102,01%**», хотя доходность при 102,01 = 20,13. Главное число завышено на 0,84 п.п., «Разница» с обещанием 5,0 вместо 5,9 п.п.; `price.prev_used=false`; кэшируется на 15 мин.
- **Связанное (R2-29, medium):** `toNum(0) = 0` проходит проверку `=== null` → **`main = 0,00%` при status ok**. Воспроизведено на проде: ВЭБ2Р-59ПО (RU000A10FAP5). ISS использует 0 как «не рассчитано»; при этом **отрицательные** доходности (43 бумаги с YIELDATPREVWAPRICE < 0, 193 с EFFECTIVEYIELDWAPRICE ≤ 0 — бумаги выше номинала) реальны, отбрасывать нужно только точный 0.
- **Фикс:** цепочка `EFFECTIVEYIELDWAPRICE↔WAPRICE → marketdata.YIELDATWAPRICE↔WAPRICE → YIELDATPREVWAPRICE↔PREVWAPRICE`; при `useMoex` цена и доходность из одной пары; `=== 0` → null для обоих полей.

#### D. Гейт `controlFailPp = 5` не применяется — `report.ts:97` — **HIGH** (R2-01)
`CONFIG.controlFailPp` не имеет ни одного потребителя; единственная реакция на расхождение — `warnings.push` в `diagnostics.warnings`, которые **не читает ни один блок, ни `digest.ts`**. Правило «> 5 — fail» есть только в офлайн-валидаторе (`tools/validate/src/rules.ts:76`, литерал 5), который не гоняется по живому API и ни разу не срабатывал (max в golden 0,22).
- Прод: RU000A10AST0 `status: ok`, yield 15,73%, fees 58,88%/42,69%, worst call 33,53%, `control_diff_pp 43.16`.
- **Распространённость:** 6 из 23 амортизируемых бумаг > 5 п.п. (ССекьюр 43, ИА ДОМ10P2 13, ТБ-9_А 12,6 — fees 29,95% при заголовке 17,4%; КВАЗАРЛ-01 5,5), неамортизируемые 0/13. На TQCB 472 амортизируемых выпуска (375 с WAPRICE) → **~100 выпусков в проде отдают несовместимые доходности без предупреждения.**
- **Фикс (поправлен оппонентом):** **не** гасить биржевую доходность (она верна); при `controlDiff > controlFailPp` обнулять производное от own: `kGrid=[]`, `fees_tax.pre/post=null` (столбик исчезает сам), убрать `fees` и `worst.call` из panels; видимый сигнал в блоке yield («наш расчёт по графику выплат не сошёлся с биржевым — показываем только биржевую доходность»); валидатор читать `CONFIG`; прокинуть `warnings` в digest. Перед включением — сравнение like-for-like по горизонту (см. F), иначе ложные срабатывания на колл-бумагах.

#### E. Амортизируемые бумаги: налог и колл — `metrics.ts:95`, `metrics.ts:72` — **HIGH→MEDIUM / HIGH**
- **Налог 13% на амортизационные выплаты** как на купон, затем «убыток» на погашении возвращает его: сумма верна (Δ −0,17 ₽), но удержание на 1–2 года раньше → постналоговая занижена ~1,4 п.п.; golden `pkb-amort` зафиксировал неверное значение.
- **Амортизация в дату колла учитывается дважды:** `couponFlows` берёт `a.t <= tH`, `horizonRed` вычитает `a.t < h.t` → выплата и в потоках, и в остатке; `hc.red` для колла = полный номинал. Доходность к коллу завышена вдвое → `min(main, call.y)` (yield-to-worst) не срабатывает. Коммит a3e69a6 сам называет удвоение остатка ошибкой — починено только для погашения (`facts.ts:200`).
- **Фикс:** в `afterTax` облагать купоны отдельно от номинала; единая граница `a.t <= h.t` в `horizonRed`/`horizon()`; `hc.red` с учётом амортизации; `recv` в period_income по тем же потокам, что `yieldOf`.

#### F. Горизонта «колл» нет в модели — `metrics.ts:44-52`, `report.ts:88`, `metrics.ts:174` — **MEDIUM**
`horizon()` возвращает `offer` только для put. Для call биржа считает `EFFECTIVEYIELD` к дате колла (`YIELDDATETYPE=OFFER`), движок берёт число без проверки `moexYDatetype`, подпись — «к погашению MATDATE».
- ТелХолБ2-6: «**17,06% к погашению 14.03.2029**», тогда как 17,06 — к коллу 25.03.2027, YTM по графику 16,29%. Контроль сравнивает own к погашению (16,39) с биржей к коллу (17,84) → ложное Δ 1,45 п.п.; при одном горизонте Δ = 0,33.
- **Фикс (поправлен):** **не** менять число — `min(main, call.y)` для колл-бумаг выше номинала прав; менять **подпись и горизонт** (`yield.horizon/horizon_date/label`, `yLine`) когда main взят с `datetype OFFER` или заменён `call.y`; `ownAtMoexPrice` считать к горизонту биржи.
